# منصة كفاءة الأثر

منصة إلكترونية متكاملة لتقييم **كفاءة الأثر** للجهات غير الربحية في المملكة، مبادرة من «استديو صناع الأثر»: تسجّل الجهة بحساب (بالبريد أو Google أو Facebook أو LinkedIn)، وتكمل بياناتها الأساسية وترفع الترخيص والأوراق المطلوبة، وتدفع رسوم التقييم، ثم تجيب عن أسئلة معايير التقييم وترفع ملفاتها، فيراجعها **خبير معتمد** معياراً معياراً، فتصدر **نتيجة غير موثقة**. ولمن يريد الشهادة النهائية يُطلب **التوثيق**: زيارة تحقق ميدانية من خبير معتمد وتقرير تعقيبي، فتصدر **شهادة كفاءة الأثر الموثقة** مع رمز QR وصفحة تحقق عامة. الأسعار الافتراضية: **500 ريال** للتقييم، و**5000 ريال** للتوثيق (يشمل التقرير التعقيبي)، وتُعدَّل من لوحة التحكم.

المنصة مبنية بـ **Next.js 15 (React 19) + Node.js + MySQL 8**، وكل الواجهات عربية من اليمين إلى اليسار.

## الأدوار والصلاحيات

| الدور | ما يراه | ما يفعله |
|---|---|---|
| **الأدمن** (`SUPER_ADMIN`) | لوحة التحكم كاملة | كل شيء: الإعدادات، والبوابات، والأسعار، والفريق وصلاحياته، والشهادات |
| **مدير الحساب** (`ACCOUNT_MANAGER`) | لوحة التحكم بحسب صلاحياته | ما يمنحه الأدمن من صلاحيات (إسناد الخبراء، جدولة الزيارات، توثيق الجهات `orgs.verify`، اعتماد التحويلات، إصدار الشهادات، أكواد الخصم…). يضيف الخبراء فقط إن مُنح «إدارة المقيّمين» |
| **الخبير** (`ASSESSOR`) | الطلبات والزيارات المسندة إليه فقط | **خبير مراجع**: يراجع ويقدّر المعايير، ويطلب الاستيضاحات، ويعتمد التقييم المكتبي. ومن يُعلَّم «خبير تحقق ميداني» تُسند إليه زيارات التحقق والتقرير التعقيبي (ولا يكون هو مراجع الطلب نفسه) |
| **الجهة** (`ORG_USER`) | بوابة الجهة | حساب واحد يدير **أكثر من جهة**: بيانات الجهة ومستنداتها، والطلب والدفع، والأسئلة، ورفع الملفات، والمراسلة المجهولة مع الخبير المراجع، والنتيجة، وطلب التوثيق، والتقرير التعقيبي، والشهادات والفواتير |

الصلاحيات معرّفة في `src/lib/permissions.ts`، وتُفحص في كل صفحة (`requireStaff`) وفي كل إجراء خادم (`assertStaff`)، لا في الواجهة فقط.

## رحلة الجهة خطوة بخطوة

شريط الرحلة الظاهر للجهة في كل صفحة يعكس سبع مراحل:

| # | المرحلة | حالة الطلب في النظام | ماذا يحدث |
|---|---|---|---|
| 1 | حساب الجهة | — | تسجيل حساب شخصي (بريد، أو Google/Facebook/LinkedIn) ثم **إضافة جهة**: نموذج من 4 خطوات (الهوية والترخيص، التواصل، الممثل المفوض، الحجم والمالية) ورفع **الترخيص والنظام الأساسي وخطاب التفويض**. المصروفات تحدد **المسار الحجمي** فوراً (ناشئ < 3 ملايين، متوسط 3–30، كبير > 30). **لا يُقدَّم طلب قبل اكتمال البيانات والمستندات**، ولا ينتظر موافقة الإدارة؛ أما **توثيق الجهة** فيراجعه فريق المنصة (مطابقة الترخيص) ويلزم لطلب زيارة التحقق وللشهادة الموثقة |
| 2 | الطلب والدفع | `AWAITING_PAYMENT` | يُنشأ طلب للسنة المالية الماضية. الدفع مطلوب قبل فتح الأسئلة (500 ريال افتراضياً شاملة الضريبة) |
| 3 | البيانات والأدلة | `DATA_COLLECTION` | أسئلة المعايير الأساسية مقسمة إلى 5 فصول مع حفظ تلقائي، ورفع الملفات بالسحب والإفلات لكل متطلب (يعمل مع أي ملف مدعوم حتى لو لم يحدد المتصفح نوعه، وتظهر رسالة واضحة عند رفض ملف). تحليل الملفات يجري داخلياً لدعم الخبير ولا يظهر للجهة |
| 4 | مراجعة الخبير | `SUBMITTED` ← `UNDER_REVIEW` ⇄ `INFO_REQUESTED` | الإرسال يتطلب الملفات الأساسية و70٪ من الأسئلة. يُسند خبير مراجع (وثانٍ اختيارياً)، وقد يطلب استيضاحات ترد عليها الجهة، وتستفسر الجهة منه عبر **المراسلة** دون أن تعرف هويته (إلا إن فعّلت الإدارة إظهار بياناته لهذا الطلب) |
| 5 | النتيجة غير الموثقة | `DESK_COMPLETED` | الدرجة والمستوى وبطاقة الكفاءة والمحاور والبوابات والتوصيات، وإفادة PDF برمز تحقق |
| 6 | التوثيق | `VERIFICATION` | تطلب الجهة التوثيق وتدفع رسومه (5000 ريال افتراضياً، تشمل التقرير التعقيبي)، فيجدول مدير الحساب الزيارة ويسند **خبير التحقق** (غير الخبير المراجع، حفاظاً على الاستقلال)، وتؤكد الجهة الموعد أو تقترح بديلاً. يبدأ الخبير الزيارة ويسجل العينة ويعدّل المستويات وينهيها، ثم يكتب **التقرير التعقيبي** وينشره للجهة |
| 7 | الشهادة الموثقة | `CERTIFIED` | يعتمد مدير الحساب الشهادة الموثقة، فتصل للجهة مع QR وصفحة تحقق عامة |

الإشعارات تصل داخل المنصة في كل انتقال (وبالبريد إن ضُبط SMTP)، وسجل النشاط يوثق كل خطوة.

## تجربة الخبير

- **قائمة عمل** مرتبة بالأقدم انتظاراً مع اكتمال ملف كل جهة.
- **مساحة التقييم**: شبكة العوامل الـ56 مقسمة بالأقسام، لكل عامل بطاقة تُظهر إجابة الجهة، ومقترح المساعد، وعدد الأدلة المرتبطة، والاستيضاحات، وعلامة «يحتاج تحقق».
- **نافذة تقييم لكل عامل**: يمين النافذة ما قدّمته الجهة (الإجابة، والتقدير الذاتي، والأدلة المرتبطة مع ما استخرجه Claude منها والاقتباس، ومقترح المساعد بنسبة الثقة)، ويسارها معيار التقدير (السؤال، والتعريف وطريقة الاحتساب، والمستويات 0–4 بأوصافها، وقاعدة التقدير، وعلامات التحذير، والمبرر، ومرجع الدليل). اختصارات لوحة المفاتيح: الأرقام 0–4 للمستوى، والأسهم للتنقل، و`Esc` للإغلاق. كل تغيير يُحفظ تلقائياً.
- **الدرجة الحية**: تُحسب في المتصفح بمحرك الاحتساب نفسه مع كل تغيير، مع البوابات ومتطلبات المسار والسقوف.
- **فلاتر**: لم يُقدّر، ومقدّر، ويحتاج تحقق، و«فرق كبير مع المساعد» (مستويان فأكثر) لمراجعة مواطن الخلاف.
- **اعتماد مقترحات المساعد للمتبقي** لتسريع العوامل غير الجوهرية، ثم **نافذة الاعتماد** بالخلاصة والتوصيات المقترحة تلقائياً من البوابات والفجوات.
- **ملف الزيارة** لخبير التحقق: بيانات التواصل (ممثل الجهة ومن يستقبله)، وزر «بدء الزيارة»، وقائمة تحقق ميدانية، ونتيجة عينة التتبع، والمعايير التي علّمها الخبير المراجع للتحقق، وسجل الزيارة الزمني، ثم تعديل المستويات في «مرحلة التحقق» دون المساس بتقديرات المرحلة المكتبية، وأخيراً محرر **التقرير التعقيبي** (ملخص، نقاط قوة، ملاحظات، توصيات) كمسودة ثم نشر للجهة.
- **المراسلة**: صندوق وارد لمحادثات الجهات؛ يرد الخبير فتظهر الرسالة للجهة باسم «الخبير المراجع» دون هويته.

## لوحة التحكم

- **نظرة عامة**: الإيرادات، والطلبات، والشهادات، ومتوسط الدرجة، ومخطط الإيرادات الشهرية، ومسار الطلبات، وأربع قوائم عمل (طلبات بانتظار الإسناد، وتحويلات بانتظار الاعتماد، وزيارات بانتظار الجدولة، وشهادات بانتظار الإصدار).
- **بحث شامل** (`/admin/search`) عن الجهات والطلبات والزيارات والمدفوعات والشهادات بالاسم أو الترخيص أو رقم الطلب.
- **طلبات التقييم**: تصفية بالحالة والمقيّم وخبير التحقق والمسار والسنة و«يحتاج إجراء» (بانتظار الإسناد، زيارة بلا خبير)، وترتيب، وترقيم صفحات. صفحة كل طلب تحوي **إسناد مرحلتين**: الخبير المراجع (وثانٍ اختيارياً) للتقرير غير الموثق، وخبير التحقق للتقرير الموثق، مع **مفتاح إظهار بيانات الخبير للجهة** لكل مرحلة (الافتراضي: مخفية للمراجع، ظاهرة لخبير التحقق). المراسلة تبقى مجهولة الهوية دائماً. ومن الصفحة: إصدار الشهادة الموثقة، وإعادة فتح الطلب أو إلغائه، والمدفوعات والملفات والسجل.
- **الجهات**: تصفية بحالة التوثيق، وصفحة لكل جهة تعرض بياناتها ومستنداتها وأعضاءها، و**توثيق الجهة** (مطابقة الترخيص مع المستند) أو إعادتها للتصحيح بملاحظة.
- **زيارات التحقق**: لوحة بالحالات (مدفوعة، مجدولة، جارية، منجزة…) والتقرير التعقيبي وتأكيد الجهة، وجدولة وإعادة جدولة وإلغاء بسبب، مع **كشف تعارض مواعيد الخبير** وقاعدة الاستقلال، وسجل زمني لكل زيارة.
- **المراسلات**: كل محادثات الجهات مع الخبراء، ويمكن لفريق المنصة الرد باسم «فريق كفاءة الأثر».
- **الجهات**، و**زيارات التحقق**، و**الشهادات** (مع الإلغاء وسببه)، و**المدفوعات والفواتير** (اعتماد التحويلات ورفضها، وتسجيل الاسترداد)، و**أكواد الخصم**، و**الفريق والصلاحيات**، و**الأسعار والفوترة** (سعر التقييم وسعر التوثيق والضريبة وبيانات البائع والحساب البنكي، مع **سجل بتغييرات الأسعار**)، و**بوابات الدفع**، و**تسجيل الدخول الاجتماعي** (Google وFacebook وLinkedIn)، و**البريد الصادر**، و**Claude** (داخلي للفريق)، و**متطلبات الملفات** (لكل مسار، مع ربطها بالعوامل)، و**المنهجية**، و**سجل النشاط**.

## الدفع وأكواد الخصم والبوابات

- **الأسعار** من «الأسعار والفوترة»: التقييم المهني 500 ريال، والتوثيق 5000 ريال (يشمل زيارة التحقق والتقرير التعقيبي)، والضريبة 15٪، مع خيار «الأسعار شاملة الضريبة». أي تعديل ينعكس على الطلبات الجديدة فوراً.
- **أكواد الخصم** من «أكواد الخصم»: نسبة أو مبلغ ثابت، لخدمة معينة أو للكل، بحد استخدام وتاريخ انتهاء. ينشئها الأدمن فتعمل في صفحة الدفع مباشرة، ويُعاد احتساب الضريبة تلقائياً. الكود الذي يغطي المبلغ كاملاً يفعّل الطلب دون بوابة.
- **بوابات الدفع** من «بوابات الدفع»، وكلها تنعكس على صفحة الدفع لحظياً:
  - **البوابة التجريبية**: تحاكي الدفع الناجح والفاشل للاختبار والتدريب. **عطّلها قبل الإطلاق.**
  - **ميسر (Moyasar)**: أدخل `Publishable Key` و`Secret Key` و`Webhook Secret` ثم فعّلها. تُنشأ فاتورة مستضافة لكل دفعة، ويعود العميل إلى `/api/payments/return` فتتحقق المنصة من الدفعة لدى ميسر قبل اعتمادها، وتستقبل الإشعارات على `/api/webhooks/moyasar`.
  - **تاب (Tap)**: أدخل `Secret Key` (و`Public Key` و`Merchant ID`) ثم فعّلها. الإشعارات على `/api/webhooks/tap`.
  - **التحويل البنكي**: يرفع العميل الإيصال، ويعتمده من يملك صلاحية «اعتماد التحويلات» من «المدفوعات».
- المفاتيح السرية **تُحفظ مشفرة** (AES-256-GCM بمفتاح مشتق من `APP_SECRET`) ولا تظهر كاملة بعد الحفظ. المنصة ترفض تفعيل وضع «إنتاج» بمفتاح اختبار.
- **أثر الدفع آلياً**: دفع التقييم ينقل الطلب إلى «تعبئة البيانات»، ودفع الزيارة ينقله إلى «زيارة التحقق»، وتصدر **فاتورة ضريبية مبسطة** برمز QR بصيغة TLV المعتمدة، وتصل الإشعارات للجهة والفريق.

## الربط مع Claude (داخلي)

تحليل الملفات واقتراح المستويات **أداة داخلية للفريق فقط**؛ لا يظهر في الموقع العام ولا في بوابة الجهة أي ذكر للذكاء الاصطناعي، وتُوصف المراجعة للجهة بأنها «تقييم مهني من خلال خبراء معتمدين». يجري التحليل في الخلفية بعد الرفع دون أن تنتظره الجهة.

المنصة تتصل بـ Claude عبر **واجهة Anthropic البرمجية (API)**. تطبيقات الويب لا تستطيع استخدام حساب claude.ai الشخصي، لذلك يُنشأ مفتاح من [console.anthropic.com](https://console.anthropic.com) ← API Keys، ويُدخل في **لوحة التحكم ← Claude والذكاء الاصطناعي** (أو في `ANTHROPIC_API_KEY`). زر «اختبار الاتصال» يتحقق منه فوراً.

ما يفعله Claude:

1. **تحليل كل ملف عند رفعه** (PDF، وصور، وWord، وExcel): نوع الوثيقة، والفترة التي تغطيها، والمتطلب الأقرب، وأهم الأرقام، والعوامل التي يقدم لها دليلاً مع مستوى مقترح متحفظ ونسبة ثقة ومبرر واقتباس، وما ينقص الملف، وملاحظات الجودة (مثل فترة غير مطابقة للسنة المقيّمة).
2. **«ما الذي ينقص ملفك؟»** للجهة: نسبة الجاهزية، والنواقص مرتبة بالأولوية (البوابات أولاً)، وثلاث خطوات تالية عملية.
3. **مستوى مقترح لكل عامل** للمقيّم عند إرسال الطلب، مع المبرر ومصدره. القرار النهائي للمقيّم دائماً.

يُطلب من Claude إخراج منظم (tool use) حتى تُحفظ النتائج حقولاً لا نصاً حراً. وعند غياب المفتاح تعمل المنصة **بتحليل القواعد** (ربط الملفات بالمتطلبات والعوامل، وحساب النواقص)، فلا يتوقف شيء. النموذج الافتراضي `claude-sonnet-5-5`، ويمكن اختيار `claude-opus-5-5` للملفات المعقدة أو `claude-haiku-5-5` للسرعة.

## الشهادة: الفترة والصلاحية

- كل طلب يقيّم **السنة المالية الماضية** بتقريرها السنوي وقوائمها المالية (مثلاً: طلب في 2026 يقيّم 2025).
- الإفادة غير الموثقة والشهادة الموثقة **تسريان حتى 31 ديسمبر من السنة الحالية** (السنة التالية للسنة المقيّمة).
- لكل إصدار رقم (`KAU-…` غير موثقة، `KAC-…` موثقة) ورمز تحقق من 10 خانات، وصفحة عامة `/verify/<الرمز>` تعرض الحالة لحظياً (سارية، أو منتهية، أو ملغاة وسببها).

## محرك الاحتساب

`src/lib/scoring.ts` تطبيق مطابق للنموذج المعتمد في الدليل المرجعي:

- معايير بمستويات 0–4 (المنهج 132 معياراً، منها 56 مركزياً تدخل في الاحتساب؛ الثابتان `CATALOG_FACTORS` و`CORE_FACTORS` في `src/lib/domain.ts`)، وأربعة محاور داخلية للاحتساب لا تُعرض معادلتها في الموقع العام: كفاءة الموارد (30)، وجودة القياس والأدلة (30)، والأثر لكل وحدة إنفاق (30)، والمساءلة (10). وزن العامل = درجته ÷ مجموع درجات محوره × نقاط المحور، ونقاطه = المستوى ÷ 4 × وزنه.
- محور الأثر يُضرب في **معامل التصميم** `Fd = 0.70 + 0.30 × (F049 + F057) ÷ 8` و**معامل الانتقاء** `Fs` (F106: 0 ← 0.90، 1 ← 0.95، 2 فأكثر ← 1.00).
- **سقوف المستوى**: F005 لا يتجاوز 2 إذا كان F002 ≤ 1، وF001 وF005 لا يتجاوزان 3 إذا كان F003 < 2.
- **البوابات** F127 ≥ 2 وF016 ≥ 2 وF056 ≥ 1، وإلا فالجهة «قيد التأهيل». **شروط الجاهزية** F048 وF055 ≥ 1 وإلا سقف «نامٍ». **متطلبات المسار** (F056، F021، F129، F004 بحسب المسار): متطلب واحد غير مستوفى ينزل مستوى، واثنان فأكثر مستويين. وسقف «متمكن» إذا كان محور الأثر المعدّل < 12، و«نامٍ» إذا < 6.
- المستويات: رائد 85+، متقدم 70+، متمكن 55+، نامٍ 40+، ناشئ دون 40.
- مؤشر نضج المحركات (DMI)، ومؤشر الأدلة، وأولويات التطوير لأعلى 12 محركاً.

الاختبارات في `tests/scoring.test.ts` تتحقق من مطابقة الدرجات لست حالات محسوبة سلفاً (منها مثال الدليل 64.7 «متمكن» وجمعيات الدراسة التجريبية).

## التشغيل المحلي

المتطلبات: **Node.js 20 أو أحدث** (مُختبر على 22)، و**MySQL 8**.

```bash
# 1) الحزم
npm install

# 2) قاعدة البيانات
mysql -uroot -p -e "CREATE DATABASE kafaat CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'kafaat'@'localhost' IDENTIFIED BY 'كلمة_مرور_قوية';
GRANT ALL ON kafaat.* TO 'kafaat'@'localhost';"

# 3) الإعدادات
cp .env.example .env      # ثم عدّل DATABASE_URL وAPP_SECRET

# 4) الجداول (واحد من الخيارين)
npm run db:push           # من المخطط مباشرة
# أو: mysql -ukafaat -p kafaat < database/schema.sql

# 5) بيانات العرض التجريبية (اختياري، يمسح الجداول ثم يعبئها)
npm run db:seed

# 6) التشغيل
npm run dev               # للتطوير على http://localhost:3000
npm run build && npm start  # للإنتاج
```

## التشغيل بـ Docker

```bash
APP_SECRET="سر-طويل-عشوائي" APP_URL="https://your-domain" docker compose up -d --build
docker compose exec app npm run db:seed   # مرة واحدة إن أردت بيانات العرض
```

يُنشئ `docker-compose.yml` قاعدة MySQL 8 بترميز utf8mb4، ويطبق المخطط عند التشغيل، ويحفظ الملفات المرفوعة وبيانات القاعدة في مجلدات دائمة (volumes).

## حدود الإصدار الحالي

- الفاتورة ضريبية مبسطة برمز QR (المرحلة الأولى من الفوترة الإلكترونية)؛ الربط مع منصة «فاتورة» للمرحلة الثانية غير مشمول.
- الاسترداد يُسجل في المنصة، وينفَّذ مالياً من لوحة البوابة.
- الحماية من تخمين كلمات المرور في الذاكرة لكل خادم؛ عند التشغيل على عدة خوادم يُنصح بطبقة حماية أمامية.
- الإشعارات داخل المنصة وبالبريد؛ الرسائل النصية غير مشمولة.
- الدخول الاجتماعي ورسائل البريد لم تُختبر مع المزودين الحقيقيين (تُختبر بخادم محاكاة)؛ تحقق منها بعد إدخال المفاتيح الفعلية.
- عدد المعايير المركزية المعلن 56 كما في بيانات المنهج؛ يُعدَّل من الثابت `CORE_FACTORS` إن اعتُمد رقم آخر.
