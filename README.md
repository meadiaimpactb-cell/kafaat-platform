# منصة كفاءة الأثر

منصة إلكترونية متكاملة لتقييم **كفاءة الأثر** للجهات غير الربحية: تسجّل الجهة، وتعبّئ بياناتها الرئيسة، وتدفع رسوم التقييم، ثم تجيب عن أسئلة العوامل الـ56 وترفع ملفاتها، فيحللها **Claude** ويخبرها بما ينقص، ويراجعها مقيّم معتمد في نوافذ تقييم لكل عامل، فتصدر **نتيجة غير موثقة**. ولمن يريد الشهادة النهائية تُطلب **زيارة تحقق** مدفوعة يجريها مستشار ميداني، فتصدر **شهادة كفاءة الأثر الموثقة** مع رمز QR وصفحة تحقق عامة.

المنصة مبنية بـ **Next.js 15 (React 19) + Node.js + MySQL 8**، وكل الواجهات عربية من اليمين إلى اليسار.

## الأدوار والصلاحيات

| الدور | ما يراه | ما يفعله |
|---|---|---|
| **الأدمن** (`SUPER_ADMIN`) | لوحة التحكم كاملة | كل شيء: الإعدادات، والبوابات، والأسعار، والفريق وصلاحياته، والشهادات |
| **مدير الحساب** (`ACCOUNT_MANAGER`) | لوحة التحكم بحسب صلاحياته | ما يمنحه الأدمن من 19 صلاحية (إسناد المقيّمين، جدولة الزيارات، اعتماد التحويلات، إصدار الشهادات، أكواد الخصم…). يضيف المقيّمين فقط إن مُنح «إدارة المقيّمين» |
| **المقيّم** (`ASSESSOR`) | الطلبات المسندة إليه فقط | يراجع ويقدّر العوامل، ويطلب الاستيضاحات، ويعتمد التقييم المكتبي. ومن يُعلَّم «مستشاراً ميدانياً» تُسند إليه زيارات التحقق |
| **الجهة** (`ORG_USER`) | بوابة الجهة | البيانات الرئيسة، والطلب والدفع، والأسئلة، ورفع الملفات، والرد على الاستيضاحات، والنتيجة، وطلب الزيارة، والشهادات والفواتير |

الصلاحيات معرّفة في `src/lib/permissions.ts`، وتُفحص في كل صفحة (`requireStaff`) وفي كل إجراء خادم (`assertStaff`)، لا في الواجهة فقط.

## رحلة الجهة خطوة بخطوة

شريط الرحلة الظاهر للجهة في كل صفحة يعكس سبع مراحل:

| # | المرحلة | حالة الطلب في النظام | ماذا يحدث |
|---|---|---|---|
| 1 | حساب الجهة | — | تسجيل حساب ثم نموذج من 3 خطوات للبيانات الرئيسة. المصروفات تحدد **المسار الحجمي** فوراً (ناشئ < 3 ملايين، متوسط 3–30، كبير > 30) |
| 2 | الطلب والدفع | `AWAITING_PAYMENT` | يُنشأ طلب للسنة المالية الماضية. الدفع مطلوب قبل فتح الأسئلة (1000 ريال افتراضياً شاملة الضريبة) |
| 3 | البيانات والأدلة | `DATA_COLLECTION` | 56 سؤالاً مقسمة إلى 5 أقسام مع حفظ تلقائي، ورفع الملفات بالسحب والإفلات لكل متطلب، وتحليل Claude لكل ملف، وتحليل «ما الذي ينقص ملفك» |
| 4 | مراجعة المقيّم | `SUBMITTED` ← `UNDER_REVIEW` ⇄ `INFO_REQUESTED` | الإرسال يتطلب الملفات الأساسية و70٪ من الأسئلة. يُسند مقيّم، وقد يطلب استيضاحات ترد عليها الجهة |
| 5 | النتيجة غير الموثقة | `DESK_COMPLETED` | الدرجة والمستوى وبطاقة الكفاءة والمحاور والبوابات والتوصيات، وإفادة PDF برمز تحقق |
| 6 | زيارة التحقق | `VERIFICATION` | تطلب الجهة الزيارة وتدفع رسومها (5000 ريال افتراضياً)، فيجدولها مدير الحساب ويسند المستشار، الذي يسجل العينة ويعدّل المستويات وينهي الزيارة |
| 7 | الشهادة الموثقة | `CERTIFIED` | يعتمد مدير الحساب الشهادة الموثقة، فتصل للجهة مع QR وصفحة تحقق عامة |

الإشعارات تصل داخل المنصة في كل انتقال (وبالبريد إن ضُبط SMTP)، وسجل النشاط يوثق كل خطوة.

## تجربة المقيّم

- **قائمة عمل** مرتبة بالأقدم انتظاراً مع اكتمال ملف كل جهة.
- **مساحة التقييم**: شبكة العوامل الـ56 مقسمة بالأقسام، لكل عامل بطاقة تُظهر إجابة الجهة، ومقترح المساعد، وعدد الأدلة المرتبطة، والاستيضاحات، وعلامة «يحتاج تحقق».
- **نافذة تقييم لكل عامل**: يمين النافذة ما قدّمته الجهة (الإجابة، والتقدير الذاتي، والأدلة المرتبطة مع ما استخرجه Claude منها والاقتباس، ومقترح المساعد بنسبة الثقة)، ويسارها معيار التقدير (السؤال، والتعريف وطريقة الاحتساب، والمستويات 0–4 بأوصافها، وقاعدة التقدير، وعلامات التحذير، والمبرر، ومرجع الدليل). اختصارات لوحة المفاتيح: الأرقام 0–4 للمستوى، والأسهم للتنقل، و`Esc` للإغلاق. كل تغيير يُحفظ تلقائياً.
- **الدرجة الحية**: تُحسب في المتصفح بمحرك الاحتساب نفسه مع كل تغيير، مع البوابات ومتطلبات المسار والسقوف.
- **فلاتر**: لم يُقدّر، ومقدّر، ويحتاج تحقق، و«فرق كبير مع المساعد» (مستويان فأكثر) لمراجعة مواطن الخلاف.
- **اعتماد مقترحات المساعد للمتبقي** لتسريع العوامل غير الجوهرية، ثم **نافذة الاعتماد** بالخلاصة والتوصيات المقترحة تلقائياً من البوابات والفجوات.
- **ملف الزيارة** للمستشار: قائمة تحقق ميدانية، ونتيجة عينة التتبع، والعوامل التي علّمها المقيّم للتحقق، ثم تعديل المستويات في «مرحلة التحقق» دون المساس بتقديرات المرحلة المكتبية.

## لوحة التحكم

- **نظرة عامة**: الإيرادات، والطلبات، والشهادات، ومتوسط الدرجة، ومخطط الإيرادات الشهرية، ومسار الطلبات، وأربع قوائم عمل (طلبات بانتظار الإسناد، وتحويلات بانتظار الاعتماد، وزيارات بانتظار الجدولة، وشهادات بانتظار الإصدار).
- **طلبات التقييم**: تصفية بالحالة وبحث، وصفحة لكل طلب للإسناد (مقيّم أول وثانٍ ومدير حساب)، وجدولة الزيارة، وإصدار الشهادة الموثقة، وإعادة فتح الطلب أو إلغائه، والمدفوعات والملفات والسجل.
- **الجهات**، و**زيارات التحقق**، و**الشهادات** (مع الإلغاء وسببه)، و**المدفوعات والفواتير** (اعتماد التحويلات ورفضها، وتسجيل الاسترداد)، و**أكواد الخصم**، و**الفريق والصلاحيات**، و**الأسعار والفوترة** (الأسعار والضريبة وبيانات البائع والحساب البنكي)، و**بوابات الدفع**، و**Claude**، و**متطلبات الملفات** (لكل مسار، مع ربطها بالعوامل)، و**المنهجية**، و**سجل النشاط**.

## الدفع وأكواد الخصم والبوابات

- **الأسعار** من «الأسعار والفوترة»: التقييم والشهادة 1000 ريال، وزيارة التحقق 5000 ريال، والضريبة 15٪، مع خيار «الأسعار شاملة الضريبة». أي تعديل ينعكس على الطلبات الجديدة فوراً.
- **أكواد الخصم** من «أكواد الخصم»: نسبة أو مبلغ ثابت، لخدمة معينة أو للكل، بحد استخدام وتاريخ انتهاء. ينشئها الأدمن فتعمل في صفحة الدفع مباشرة، ويُعاد احتساب الضريبة تلقائياً. الكود الذي يغطي المبلغ كاملاً يفعّل الطلب دون بوابة.
- **بوابات الدفع** من «بوابات الدفع»، وكلها تنعكس على صفحة الدفع لحظياً:
  - **البوابة التجريبية**: تحاكي الدفع الناجح والفاشل للاختبار والتدريب. **عطّلها قبل الإطلاق.**
  - **ميسر (Moyasar)**: أدخل `Publishable Key` و`Secret Key` و`Webhook Secret` ثم فعّلها. تُنشأ فاتورة مستضافة لكل دفعة، ويعود العميل إلى `/api/payments/return` فتتحقق المنصة من الدفعة لدى ميسر قبل اعتمادها، وتستقبل الإشعارات على `/api/webhooks/moyasar`.
  - **تاب (Tap)**: أدخل `Secret Key` (و`Public Key` و`Merchant ID`) ثم فعّلها. الإشعارات على `/api/webhooks/tap`.
  - **التحويل البنكي**: يرفع العميل الإيصال، ويعتمده من يملك صلاحية «اعتماد التحويلات» من «المدفوعات».
- المفاتيح السرية **تُحفظ مشفرة** (AES-256-GCM بمفتاح مشتق من `APP_SECRET`) ولا تظهر كاملة بعد الحفظ. المنصة ترفض تفعيل وضع «إنتاج» بمفتاح اختبار.
- **أثر الدفع آلياً**: دفع التقييم ينقل الطلب إلى «تعبئة البيانات»، ودفع الزيارة ينقله إلى «زيارة التحقق»، وتصدر **فاتورة ضريبية مبسطة** برمز QR بصيغة TLV المعتمدة، وتصل الإشعارات للجهة والفريق.

## الربط مع Claude

المنصة تتصل بـ Claude عبر **واجهة Anthropic البرمجية (API)**. تطبيقات الويب لا تستطيع استخدام حساب claude.ai الشخصي، لذلك يُنشأ مفتاح من [console.anthropic.com](https://console.anthropic.com) ← API Keys، ويُدخل في **لوحة التحكم ← Claude والذكاء الاصطناعي** (أو في `ANTHROPIC_API_KEY`). زر «اختبار الاتصال» يتحقق منه فوراً.

ما يفعله Claude:

1. **تحليل كل ملف عند رفعه** (PDF، وصور، وWord، وExcel): نوع الوثيقة، والفترة التي تغطيها، والمتطلب الأقرب، وأهم الأرقام، والعوامل التي يقدم لها دليلاً مع مستوى مقترح متحفظ ونسبة ثقة ومبرر واقتباس، وما ينقص الملف، وملاحظات الجودة (مثل فترة غير مطابقة للسنة المقيّمة).
2. **«ما الذي ينقص ملفك؟»** للجهة: نسبة الجاهزية، والنواقص مرتبة بالأولوية (البوابات أولاً)، وثلاث خطوات تالية عملية.
3. **مستوى مقترح لكل عامل** للمقيّم عند إرسال الطلب، مع المبرر ومصدره. القرار النهائي للمقيّم دائماً.

يُطلب من Claude إخراج منظم (tool use) حتى تُحفظ النتائج حقولاً لا نصاً حراً. وعند غياب المفتاح تعمل المنصة **بتحليل القواعد** (ربط الملفات بالمتطلبات والعوامل، وحساب النواقص)، فلا يتوقف شيء. النموذج الافتراضي `claude-sonnet-5-5`، ويمكن اختيار `claude-opus-5-5` للملفات المعقدة أو `claude-haiku-5-5` للسرعة.

## الشهادة: الفترة والصلاحية

- كل طلب يقيّم **السنة المالية الماضية** بتقريرها السنوي وقوائمها المالية (مثلاً: طلب في 2026 يقيّم 2025).
- الإفادة غير الموثقة والشهادة الموثقة **تسريان حتى 31 ديسمبر من السنة الحالية** (السنة التالية للسنة المقيّمة).
- لكل إصدار رقم (`KAU-…` غير موثقة، `KAC-…` موثقة) ورمز تحقق من 10 خانات، وصفحة عامة `/verify/<الرمز>` تعرض الحالة لحظياً (سارية، أو منتهية، أو ملغاة وسببها).

## محرك الاحتساب

`src/lib/scoring.ts` تطبيق مطابق للنموذج المعتمد في الدليل المرجعي:

- 56 عاملاً بمستويات 0–4، وأربعة محاور: كفاءة الموارد (30)، وجودة القياس والأدلة (30)، والأثر لكل وحدة إنفاق (30)، والمساءلة (10). وزن العامل = درجته ÷ مجموع درجات محوره × نقاط المحور، ونقاطه = المستوى ÷ 4 × وزنه.
- محور الأثر يُضرب في **معامل التصميم** `Fd = 0.70 + 0.30 × (F049 + F057) ÷ 8` و**معامل الانتقاء** `Fs` (F106: 0 ← 0.90، 1 ← 0.95، 2 فأكثر ← 1.00).
- **سقوف المستوى**: F005 لا يتجاوز 2 إذا كان F002 ≤ 1، وF001 وF005 لا يتجاوزان 3 إذا كان F003 < 2.
- **البوابات** F127 ≥ 2 وF016 ≥ 2 وF056 ≥ 1، وإلا فالجهة «قيد التأهيل». **شروط الجاهزية** F048 وF055 ≥ 1 وإلا سقف «نامٍ». **متطلبات المسار** (F056، F021، F129، F004 بحسب المسار): متطلب واحد غير مستوفى ينزل مستوى، واثنان فأكثر مستويين. وسقف «متمكن» إذا كان محور الأثر المعدّل < 12، و«نامٍ» إذا < 6.
- المستويات: رائد 85+، متقدم 70+، متمكن 55+، نامٍ 40+، ناشئ دون 40.
- مؤشر نضج المحركات (DMI)، ومؤشر الأدلة، وأولويات التطوير لأعلى 12 محركاً.

الاختبارات في `tests/scoring.test.ts` تتحقق من مطابقة الدرجات لست حالات محسوبة سلفاً (منها مثال الدليل 64.7 «متمكن» وجمعيات الدراسة التجريبية).

## التشغيل المحلي

المتطلبات: **Node.js 20 أو أحدث** (مُختبر على 22)، و**MySQL 8**.

```bash
# 1) الحزم
npm install

# 2) قاعدة البيانات
mysql -uroot -p -e "CREATE DATABASE kafaat CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'kafaat'@'localhost' IDENTIFIED BY 'كلمة_مرور_قوية';
GRANT ALL ON kafaat.* TO 'kafaat'@'localhost';"

# 3) الإعدادات
cp .env.example .env      # ثم عدّل DATABASE_URL وAPP_SECRET

# 4) الجداول (واحد من الخيارين)
npm run db:push           # من المخطط مباشرة
# أو: mysql -ukafaat -p kafaat < database/schema.sql

# 5) بيانات العرض التجريبية (اختياري، يمسح الجداول ثم يعبئها)
npm run db:seed

# 6) التشغيل
npm run dev               # للتطوير على http://localhost:3000
npm run build && npm start  # للإنتاج
```

## التشغيل بـ Docker

```bash
APP_SECRET="سر-طويل-عشوائي" APP_URL="https://your-domain" docker compose up -d --build
docker compose exec app npm run db:seed   # مرة واحدة إن أردت بيانات العرض
```

يُنشئ `docker-compose.yml` قاعدة MySQL 8 بترميز utf8mb4، ويطبق المخطط عند التشغيل، ويحفظ الملفات المرفوعة وبيانات القاعدة في مجلدات دائمة (volumes).

## متغيرات البيئة

| المتغير | الوصف |
|---|---|
| `DATABASE_URL` | رابط MySQL، مثل `mysql://kafaat:pass@localhost:3306/kafaat` |
| `APP_SECRET` | سر طويل عشوائي (64 حرفاً فأكثر) لتشفير مفاتيح البوابات ومفتاح Claude. **تغييره بعد حفظ المفاتيح يتطلب إعادة إدخالها** |
| `APP_URL` | الرابط العام (روابط العودة من بوابات الدفع، ورابط التحقق في QR الشهادة) |
| `STORAGE_DIR` | مجلد الملفات المرفوعة (افتراضياً `./storage/uploads`) |
| `ANTHROPIC_API_KEY` | اختياري؛ مفتاح Claude الافتراضي إن لم يُدخل من لوحة التحكم |
| `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASS` `SMTP_FROM` | اختيارية؛ لإرسال الإشعارات بالبريد أيضاً |
